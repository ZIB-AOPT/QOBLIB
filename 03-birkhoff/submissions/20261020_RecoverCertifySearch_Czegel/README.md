# RecoverCertifySearch — Minimum Birkhoff Decomposition (QOBLIB 03)

Submitter: András Czégel (Bentax Plus). Date: 2026-10-20. Hardware: Apple MacBook Pro, M4 Pro (8 performance + 4 efficiency cores), 24 GB RAM.

## Runs

Five independent runs with the seeds 0 to 4 (6 threads each, two instances at a time). In every run, each instance gets 60 s wall clock, and the instances without a proof of optimality get a second round of 600 s, which starts from scratch. The result of a run is the shorter decomposition of its two rounds. Each instance reports the shortest decomposition over the five runs, the largest lower bound over the runs that holds for real weights, and the number of runs that reached this length (`# Successful Runs`, with ε = 0). The total runtime of a run is the time of both rounds, and its time to solution is the time from the start of the run until it first found a decomposition of its final length, so the second round counts from the end of the first. The CPU runtime is the measured CPU time of all threads in both rounds; it was measured for the runs with the seeds 1 to 4. Total runtime, time to solution and CPU runtime are means over the runs; the remarks of each instance give the mean, median and standard deviation of the length, the runtime and the time to solution. The objective time series gives the incumbent of every run over both rounds, the second round shifted by the runtime of the first. Every optimality bound comes from these runs.

All decompositions are **exact**: the weights have the precision of the data (whole numbers at the instance's scale), no tolerance, checked with the official checker. The solver reads only the matrix; the planted decomposition stored in the instance files is never used.

Every optimality bound holds for real weights: it is the degree or the two-line bound. The runs also prove larger bounds with SAT certificates on 50 small dense instances, but these bounds hold only for weights with the precision of the data. They are given in the remarks of these instances and are not used as optimality bounds. Their proofs (LRAT) would take several gigabytes and are not included.

## Certificates

Each instance folder has a certificate of its optimality bound, `<instance>_certificate.json`. Every certificate holds for real weights (`"valid_for": "real weights"`). Lines are named `row i` and `column j`, numbered from 1, and all values are entries of `scaled_doubly_stochastic_matrix`. A certificate proves that every decomposition, also with real weights, has at least `bound` terms, in one of two ways (Sect. 3.3 and the appendix of the article):

- `"method": "degree"`: the `line` has `bound` nonzero entries. Every term covers exactly one position of each line.
- `"method": "two-line"`: the two-line bound of the two `lines`, with p and q nonzero entries. After `equal_pairs` pairs of equal values of the two lines are removed, the `unmatched` values of each line remain. Their block number γ* is the largest number of parts into which they can be split such that in every part the values of the two lines have the same sum. With g = `block_number_at_most` ≥ γ*, every decomposition has at least p + q − `equal_pairs` − g = `bound` terms. `block_number_proof` gives the reason for γ* ≤ g, with m unmatched values:
  - `quick`: every part has at least three values; a part of three values is {x | y, z} with x = y + z, where x is a value of one line and y, z are values of the other line; every other part has at least four values. With t the number of unmatched values that are the sum of two unmatched values of the other line and s = min(t, ⌊m/3⌋), g = s + ⌊(m − 3s)/4⌋.
  - `exact`: g = γ*, which can be computed directly (here at most 32 unmatched values).
  - `packing`: the packing bound with parts of at most T = `max_block` values. `duals` gives a nonnegative integer for every unmatched value; y_e is this integer divided by `dual_denominator`. For every part Z with at most T values (values of both lines with the same sum), the y_e of Z sum to at least 1 − |Z|/(T + 1). Then g = ⌊m/(T + 1) + Σ y_e⌋.

The program `check_certificate` of the code repository checks a certificate against the instance file, for example `check_certificate qbench_04_dense.json B4_16_1/B4_16_1_certificate.json`.

## Method

Two chains run side by side in every run and stop when they meet; then the result is proven optimal.

1. *Solution chain.* Sparse instances: the weights are read from how often each value occurs (frequency rule), then placed position by position by fixing by unique subset sums, which provably makes no wrong choice (largest weight first and an enumeration of weight sets run in parallel). Dense instances: the Birkhoff algorithm with the zeroing rule, which makes as many entries zero as possible, a beam search over zeroing steps, SAT re-optimization of the small-weight tail, and large neighborhood search. Every decomposition is checked before it is accepted.
2. *Bound chain.* The degree (most nonzero entries in a line); the two-line bound (how many equal-sum blocks two lines can be split into, counted exactly or bounded by a packing bound that is checked in integer arithmetic); SAT certificates that fewer terms are impossible with weights of this precision (split into cases for n <= 7).

Definitions and proofs are in the accompanying article. Source code: Rust. Reference: https://arxiv.org/abs/2610.25837 (article), https://github.com/tg90000/rcs-birkhoff (code).
